A short guide to where things live, so you can change them with confidence. It is a snapshot of the code, and it can drift as the project changes.

What it is

A proof of concept for a safety manager. It watches one camera view, finds workers, flags a missing helmet or hi-vis vest, sounds a siren when someone enters a danger zone, and records every incident in an Event Log with a snapshot. It runs entirely on one laptop and has three main pieces:

  • Python backend (backend/app/): reads the camera or a recorded clip, detects people and PPE with YOLO, applies the safety rules, and stores the incidents.
  • Next.js dashboard (frontend/): shows the video, the banner, the three cards, the alert list and the Event Log, and plays the siren.
  • Local files: incident snapshots in backend/data/snapshots/, and model weights in backend/models/. There is no database and no cloud.

A 3-stop route through the code

This is a reference route. Open each file and search for the name shown.

  1. The loop: backend/app/camera.py, search def _run. It reads a frame, asks the detector for people and PPE, passes them to the rules, saves any new incident (self.events.add) and sends the drawn frame to the browser.
  2. The decision: backend/app/rules.py, search class RulesEngine then def update. Look for inside_now: a worker's feet position is tested against the zone, and a new incident is created only when someone goes from outside to inside. The same function gives each person a stable worker number and checks helmet and vest.
  3. What you see: frontend/app/page.tsx, search useSiren. The dashboard polls the backend, and the siren plays while the zone has someone in it. The banner is AlertBanner in frontend/components/VideoPanel.tsx.

A practice to reuse

Reproduce a flaky behavior with a small simulation, and track one number before and after the fix.

In this project the worker numbers kept climbing for a single person. A simulated video with detection gaps gave 12 tracker IDs for 4 people with the original settings and 4 after the fix. A later live test showed the same symptom from a different cause (duplicate boxes on a close-up face), so a second rule was added and tested the same way. The record is in devpost/checklist.md under Revisions.

On another project: when something behaves oddly, write down what you expected, build the smallest repeatable test that shows the problem, and pick one number to watch. It tells you whether a fix worked and whether a new symptom is the same problem or a different one.

Run it again

# Terminal 1 (backend)
cd backend
source .venv/bin/activate
uvicorn app.main:app --port 8000

# Terminal 2 (dashboard)
cd frontend
npm run dev
# open http://localhost:3000, then click Start

First time? See the setup steps in README.md (install the requirements, run python download_weights.py, and run npm install). Recorded plays the first video in backend/media/. The backend does not reload by itself, so restart it after changing code.
